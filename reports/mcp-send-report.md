# Autonomous Nitrosend MCP run (Claude Code headless)

- Goal given to the agent, one sentence, no walkthrough: "Connect to the Nitrosend MCP server and send a short email to proof@dogfood.nitrosend.net using the hosted sender hello@utalabs2.nitrosend.net."
- Setup (before the client run, headless path): account created and API key issued via `POST https://api.nitrosend.com/v1/signup` and `POST /v1/my/api_keys`; hosted sender activated with `POST /v1/my/brands/<sid>/prepare_sending {"subdomain":"..."}` → hello@utalabs2.nitrosend.net (active immediately). No browser, no OAuth step; the client connected with the API key as a Bearer token.
- Commands/runtime: Node 24.x sandbox; Claude Code installed with `npm install -g @anthropic-ai/claude-code` (v2.1.309); run as `claude -p "<goal>" --mcp-config .mcp.json --dangerously-skip-permissions`; `.mcp.json` declares `{"mcpServers":{"nitrosend":{"type":"http","url":"https://api.nitrosend.com/mcp","headers":{"Authorization":"Bearer <key>"}}}}`.
- Client and model: Claude Code 2.1.309 in headless print mode; model served through a local Anthropic-compatible bridge (ANTHROPIC_BASE_URL) backed by GLM (Z.ai). The agent did everything itself; a person did zero steps during the run.
- Time from connecting to first send: ~2 minutes (client start to queued send in the same session; the send tool returned "successfully queued" and the message shows status `sent`).
- Slowest step: the first launch hit the turn cap without acting — project-scoped `.mcp.json` servers start as "Pending approval" even in `--dangerously-skip-permissions` print mode. Fixed with `{"enabledMcpjsonServers":["nitrosend"]}` in `.claude/settings.json` plus the explicit `--mcp-config` flag.
- Defect with exact repro: `nitro_send_message` does not accept a `from` field — calling it with `{"channel":"email","to":"proof@dogfood.nitrosend.net","from":"hello@utalabs2.nitrosend.net",...}` fails schema validation (`value at /from ...` additionalProperties error); the sender is silently inferred from the brand. Neither the quickstart nor the MCP README documents that the hosted sender is chosen automatically.
- Change I would make: document headless enablement of project-scoped MCP servers (`enabledMcpjsonServers`) on the Claude Code integration page, and state explicitly that `nitro_send_message` takes no `from` and uses the brand sender.
