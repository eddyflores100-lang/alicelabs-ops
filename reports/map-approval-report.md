# Approving an agent-held campaign from its MAP description

- Install and commands: `npm i mailschema@0.3.3` then `npx mailschema description description.json --json`. Safe Mode was turned on with `PATCH /v1/my/account {"safe_mode_enabled":true}`; the campaign was asked for by the agent with an API key (REST `POST /v1/my/campaigns`, audience set via `trigger_attributes`, then `nitro_control_delivery schedule` over the MCP server with the Bearer key), hold state `awaiting_approval`, recipient = the account's own address.
- Time from Safe Mode on to decision: ~35 minutes (16:35 UTC → 17:10:29 UTC decision; the approved campaign then completed at its 17:26 UTC slot).
- The approval email's Mail Action description was validated unedited: `mailschema description description.json --json` → `{"valid":true,"id":"urn:uuid:108dac0b-9889-56dd-93ac-a6324ee33a21","digest":"sha-256:1609e0dbf7aa8b6d5fa8aef0bf3c1926e918a31e391062627f4da71ee0ef9de4"}` (Campaign Send Approval 0.1, profile map/0.3).
- Recomputing `terms.version`: canonicalize the description without its `terms.version` field (JSON with sorted keys, no whitespace, UTF-8) and hash with SHA-256 → `sha-256:b510acad68d9b0f20fd7eb110b2176ef3becb5ed046a4b511562613fd8ad34f9`, exactly the value the service declared in `terms.version`.
- Decision: approve. Why: the description's content digest, sender (hello@utalabs2.nitrosend.net), audience (1 contact list, 1 recipient = our own address) and schedule all matched the held campaign; the body had no merge tags and went only to the account's own address; terms.id pointed at the approval resource the decision was posted to (`POST /v1/my/map/approvals/296/ {"decision":"approve","version":"sha-256:b510…"}`).
- Step that slowed most: locating the MAP description. Our mailbox provider truncates large HTML emails, so the email copy was cut off; the identical, unedited description was recovered from `GET /v1/my/map/approvals/296/` (same `@id`, same `terms.version`).
- Defect with exact repro: approval decision receipts are not reliably emitted. The first decision (`POST /v1/my/map/approvals/295/`, 16:48:54 UTC) produced no receipt email after 28+ minutes; an identical second loop (`…/296/`, 17:10:29 UTC) produced the receipt email in about 6 minutes. No doc explains receipt batching.
- Change I would make: expose each approval's MAP description as a standalone machine URL (e.g. `…/map/approvals/296.json`) so any client can fetch and verify it without parsing email HTML.
